Secret Privacy Policy

Last updated: 19 November 2026

Secret is a Windows desktop app that lets you approve access to specific entries in your KeePass database from a terminal or an agent. The developer does not receive your vault, master password, key file, or entry contents.

Vault access on your PC

You choose a KeePass database and its key file using the app's file browser. Secret reads the database after you unlock it. It does not modify or upload your database or key file. The unlocked database and session approvals are held in the broker process until you lock or reload the vault, or close the broker. Locking cancels pending approvals, stops child commands started by Secret, disposes the unlocked database, and clears session approvals. You can enable an inactivity timeout; it is off by default and waits for active requests to finish. A separate option locks the vault when your Windows session locks. It is also off by default; when enabled it cancels active approvals and commands immediately and requires a fresh vault unlock.

The master password is used to unlock your local database. If you choose Remember on this device, Secret encrypts it with a key that only your Windows Hello gesture can unlock and stores the encrypted result in Windows Credential Manager, associated with your database and key-file paths. The app never saves the master password in plain text. Plain-text credentials saved by earlier versions are deleted when this version starts.

Settings and secure storage

Secret saves the database path, optional key-file path, approval-channel choices, the paths of two optional ntfy account entries in your vault, and locking and session preferences in your user profile on this PC. The ntfy server URL, topics, account names and passwords stay inside your KeePass vault. It ships with no configured vault or notification endpoint.

You can change your file paths in Settings if you move the database or key file. You can remove remembered master passwords, clear the ntfy connection, and clear the request history in Settings.

Terminal and agent access

The local broker communicates with programs running as your Windows user through a named pipe restricted to that user. Requests include an agent-provided identifier, an entry path, a reason, a timeout and, for secret run, the command line, working folder and any environment variables the caller chose to forward. The broker also records which processes sent the request. The identifier scopes session approvals; it is not proof of an agent's identity.

After approval, secret get returns the requested entry fields or TOTP code to the requesting program. With secret run, Secret starts the approved command and gives it only the approved values: the password or TOTP code, selected fields, or attachments written to a temporary file that is deleted when the command ends. Those programs can use the supplied data according to their own behavior. Only approve requests and commands you trust.

Secret redacts exact secret values from forwarded child output. It cannot protect transformed or encoded values, or prevent an approved child process from using a credential at its intended destination.

Request history

Secret keeps a local request history in your user profile so you can review it under Settings > Activity: the time, entry path, reason, command line, requesting process names, agent identifier and decision. It never contains entry values. It is limited to about 4 MB and you can clear it at any time.

Optional ntfy notifications

Remote approvals are off by default. When you enable them, Secret connects over HTTPS to the ntfy server you configure. The server and any notification delivery services you use can receive your IP address, authenticated account information, topic names, a compact approval notification containing the requested entry path, the request reason, what receives the secret, the command line and folder for secret run, the requesting process names, a shortened agent identifier and an expiry time, random answer values, and approval actions and responses. Each notification includes a short-lived access token for your action account, created for that request and deleted afterwards, so your notification client can submit your choice. Treat your topics and notification subscriptions as sensitive.

Request paths and reasons can themselves be sensitive and may appear on your phone's lock screen. Keep notification subscriptions private. Secret's remote notification does not include retrieved entry fields, vault passwords, TOTP codes or setup seeds, master passwords, or key-file contents. The short agent identifier is a scope hint, not proof of identity. Your ntfy server's retention rules and privacy policy apply to its stored messages. Use a server you trust, private topics, and accounts with restricted topic permissions. Disabling remote approvals stops future remote approval requests. It does not remove messages already stored by that service.

Clipboard

Secret copies the bundled agent skill, setup instructions or a command example to your clipboard only when you click the corresponding Copy button. The app does not copy vault secrets to the clipboard as part of that action. Windows clipboard history or synchronization may retain copied text according to your Windows settings.

Analytics and diagnostics

Secret contains no advertising, analytics, or developer-operated telemetry service. Windows, .NET, the Windows App SDK, and the Microsoft Store may handle diagnostics according to your Windows and Microsoft account settings. If you contact support, the developer receives your email address and the information you choose to send, and uses it to respond.

Removing data

Before uninstalling, use Settings to forget remembered master passwords if you want to remove their encrypted Credential Manager entries, and clear the request history if you want to remove it. Credential Manager entries can outlive app removal. Depending on Windows packaging and virtualization, app settings may be removed with the package; any remaining settings can be removed from the secret-broker folder in your user profile. Secret never deletes your original KeePass database or key file. Remote ntfy messages must be removed according to your server's controls.
